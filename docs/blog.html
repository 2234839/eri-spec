Beyond Text: Why AI Agents Need Interactive UI

Published: 2026-05-15

The Text Trap

Every AI Agent today has the same problem. You ask it to calculate something, and it responds with:

99.5 × 3 = 298.5

Correct. But now you want to see 4 items. Or 5. Or with 8% tax. Each variation means another round of conversation — describe what changed, wait for a response, describe the next change.

The problem isn't accuracy. The problem is the medium. Not just calculations — charts need adjustable axes, forms need editable fields, color palettes need draggable sliders. Every time, the Agent forces you back into text. The ecosystem has solved input. It hasn't solved output.

Enter ERI

ERI (Embedded Result Interface) is a convention for making Agent output interactive. Your web app appears as a live, editable UI inside any Agent conversation — ChatGPT, Claude, Gemini, any of them. You control the experience. The user interacts directly — no Agent in the loop.

No new protocols. No SDKs. No platform approval. Just a skill.md and a URL.

---
name: notecalc
description: Math calculator with variables and unit conversion.
---

## Workflow
1. Parse user request into expressions
2. Call POST /api/calculate with expressions
3. Embed result as iframe: https://app.com/embed#encoded_data
4. Output as iframe (fallback to plain text)

10 minutes to write. Half a day for the embed page. Zero platform changes. Ship today. Try it now.

Why ERI First

Each approach trades reach for richness:

  • MCP Apps give you a sandboxed runtime and distribution via the MCP ecosystem — but only users on MCP-enabled platforms see your app.
  • A2UI gives you native rendering (mobile, accessibility) — but only on platforms that ship an A2UI renderer.
  • ERI gives you every platform today — because it's just a URL in an iframe. No runtime, no renderer, no platform buy-in.

The embed page you build for ERI is the same page you'd package for MCP Apps later. ERI is the on-ramp: ship once at zero cost, adopt richer protocols when your target platforms support them.

ERI has real trade-offs (snapshot-based, no native APIs). See Limitations in the spec for the full list.
