1. 定义

ERI（Embedded Result Interface，嵌入式结果界面）是一种让 Agent 输出变为可交互的约定。Agent 处理用户请求后，输出嵌入式 UI（iframe）而非纯文本——只需一个 skill.md 和一个 URL。无需新协议，无需 SDK。

角色职责
Agent理解意图、调用 API、构造嵌入 URL、输出 UI
提供者编写 skill.md 并提供一个 HTTPS 嵌入页面（约 40 行）
平台渲染 iframe（大多数已支持）

快照式输出——Agent 不监听已输出的界面，每次新指令生成全新嵌入（见第 3 节）。第三方应用独立运行——只需提供一个 HTTPS 页面。

2. 工作流

1. 理解意图提取参数
→
2. 调用 API获取结构数据
→
3. 构造 URL编码参数
→
4. 输出 UIiframe / 纯文本

步骤 1 和 3 是 Agent 的天然能力。涉及外部系统的两个步骤：

2.1 调用 API Agent

Agent 从服务端调用第三方应用的 API（不是从用户浏览器）。标准 HTTP，结构化 JSON。无需配置 CORS。

POST /api/calculate
Body: {"expr": "99.5 * 3"}
Response: {"expr": "99.5 * 3", "result": 298.5}

2.2 输出 UI Agent 平台

<iframe src="https://app.example.com/embed#encoded_data" width="100%" height="400"></iframe>

支持在 Agent 输出中渲染 iframe 的平台包括 ChatGPT、Claude、Gemini 以及大多数基于 Web 的 Agent UI。它们通常会自动添加 sandbox 属性。如果平台不支持 iframe，ERI 会降级为纯文本输出。

3. 对话流程

iframe 内的编辑不会通知 Agent。每轮新对话：

  1. Agent 从上下文中读取上一次的结果
  2. 结合新输入，重新调用 API
  3. 输出全新的嵌入界面（旧界面不更新）

上下文来自 Agent 平台的对话历史——Agent 能看到自己之前的文字输出（包括 API 结果）。无需额外的状态机制。

用户: "帮我算 3 件商品，每件 99.5 元"
Agent: 调用 API → 输出 iframe 显示 99.5 * 3 = 298.5

（用户在 iframe 中修改数值，Agent 不感知）

用户: "再加上 8% 的税"
Agent: 读取上下文（上次结果：298.5），调用 API 传入 298.5 * 1.08
       → 输出新 iframe 显示 298.5 * 1.08 = 322.38

4. Skill 编写 提供者

skill.md 放在 Agent 能发现的位置——可以是自定义指令、GPT Action、Claude 技能文件，或平台提供的任何 Agent 行为定义机制。格式在所有平台上都一样。

一个最小化的 ERI Skill：

---
name: 工具名称
description: 工具描述
---
## 工作流
1. 从用户输入中提取参数
2. 调用 API：POST https://api.example.com/calculate
   Body: {"expr": "表达式"}
3. 用 API 响应构造嵌入 URL：
   https://app.example.com/embed#URLEncode({"expr":"...","result":...})
4. 输出为 iframe（平台无法渲染时降级为纯文本）

Agent 读取这个工作流，执行每一步，输出 iframe。

Frontmatter（name、description）遵循标准 YAML 约定。## 工作流 部分是自由格式——用 Agent 能理解的自然语言编写即可。无需特殊语法。

5. 嵌入式页面要求 提供者

要求说明
HTTPS必须使用 HTTPS
URL 参数读取从 URL hash 中读取初始状态（推荐），或使用 query 参数
自包含所有交互自行处理。不依赖宿主 JS/CSS。响应式布局。
postMessage （可选）iframe 内变化可通过 postMessage 通知宿主
主题适配 （可选）读取 URL 参数或宿主颜色方案适配明暗主题

最小嵌入页面示例

Agent 在服务端调用 API，通过 URL hash 将结果传递给嵌入页面。页面只负责渲染——iframe 内无需任何计算逻辑。

<!DOCTYPE html>
<html>
<body>
<div id="out" style="font-size:24px"></div>
<script>
  /** Agent 通过 hash 传入 JSON: {"expr":"99.5*3","result":298.5} */
  const data = JSON.parse(
    decodeURIComponent(location.hash.slice(1))
  );
  document.getElementById('out').textContent =
    data.expr + ' = ' + data.result;
</script>
</body>
</html>

10 行代码。部署到任意 HTTPS 主机即可。

6. 安全

角色规则
平台为 iframe 添加 sandbox="allow-scripts allow-same-origin"。不得将用户凭证传递给第三方 iframe。
提供者不依赖 document.cookie（沙箱环境可能不可用）。不使用 window.opener 或 window.top。所有输入做 XSS 防护。

7. 渐进等级

等级能力谁需要做什么
0纯文本输出Agent 即可——不需要其他任何配合
1iframe 嵌入提供者 嵌入页面 + 平台 iframe 支持（大多数平台已有）
2双向通信Level 1 + 提供者 平台 双方实现 postMessage

Level 2 适用于平台需要对 iframe 内的用户编辑做出响应的场景（如自动保存、实时预览）。使用 postMessage 并指定具体 origin——绝不使用 "*"：

// iframe → Agent 平台：通知用户修改了某个值
window.parent.postMessage({
  type: "eri:valueChanged",  // 必须以 "eri:" 开头
  path: "items.price",       // 所修改字段的点分路径
  value: 199                 // 新值
}, "https://agent-platform.example.com");

// Agent 平台 → iframe：向嵌入页面推送更新数据
iframe.contentWindow.postMessage({
  type: "eri:update",
  data: { items: [...], total: 597 }
}, "https://your-app.example.com");

8. 适用场景

适合：计算工具、表单/问卷、数据可视化、文档编辑、设计工具、代码编辑器——任何用户想要微调 Agent 输出的场景。

不适合：纯信息查询（不需要交互）、长文本生成、实时同步（ERI 是快照式的）。

9. 局限性

  • 快照式输出——Agent 无法实时看到 iframe 内的编辑。使用 Level 2 postMessage 可实现双向同步。
  • 设备能力受限——沙箱 iframe 对设备 API（GPS、摄像头等）的访问受限。仅支持标准 Web 能力。
  • 不可被搜索引擎索引——iframe 内容对搜索引擎不可见（对 Agent 输出场景无影响）。

10. 行业格局

交互式 Agent 输出存在三种方案：

  • ERI — 通过 URL 嵌入任何 Web 应用。所有平台通用。
  • MCP Apps（Anthropic & OpenAI）— MCP 生态中的沙箱小应用。仅限 MCP 平台。
  • A2UI（Google）— Agent 以 JSON 声明 UI，客户端原生渲染。仅限 A2UI 平台。

ERI 是入口：最广覆盖、最小代价。今天嵌入，等平台支持更丰富的协议时再升级。详细对比见博客文章。
