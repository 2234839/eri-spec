采用 ERI — 团队指南

在组织内评估、规划并上线交互式 Agent 输出。

ERI 适合你吗？

ERI 适合以下情况：

  • 已有 Web 应用，想让它在任何 Agent 对话中被嵌入
  • 作为第三方服务提供者，希望自己的应用在 ChatGPT、Claude、Gemini 上都能用
  • 想今天就上线，不等平台 SDK 或审批
  • 更看重控制自己的嵌入体验，而非依赖平台渲染器

ERI 不适合以下情况：

  • 你在构建一个自己渲染 UI 组件的平台（用 A2UI）
  • 你完全投入 MCP 生态（用 MCP Apps）
  • 你需要实时双向同步（ERI 是快照式的）

采用清单

第一阶段：试点（1 天）

  • 选择一个现有 Web 应用进行嵌入
  • 创建一个精简的 /embed 路由（约 40 行代码）
    • 从 URL hash 或 query 参数读取初始状态
    • 自包含——不依赖宿主页面
    • 使用 HTTPS
  • 按照规范写一个 skill.md
  • 在你的 Agent 平台上测试——确认 iframe 能正确渲染

第二阶段：集成（1 周）

  • 确认 iframe 渲染时添加了 sandbox="allow-scripts allow-same-origin"
  • 测试不同嵌入宽度下的响应式表现
  • 确认嵌入页面没有使用 document.cookie、window.top 或 window.opener
  • 处理边界情况：无效 URL 参数、慢网络、空状态

第三阶段：打磨（可选）

  • 通过 URL 参数或 prefers-color-scheme 添加主题适配（亮/暗）
  • 实现 postMessage 以支持 Level 2 双向通信
  • 为无效 URL 参数添加错误处理
  • 监控嵌入页面的性能和加载时间

常见疑问

"iframe 不是过时了吗？"

没有——每个主要的 Agent 平台（ChatGPT、Claude、Gemini）今天都在渲染 iframe。iframe 是 Web 嵌入东西的方式。它能用。

"安全怎么办？"

Agent 平台会对 iframe 加沙箱。你的嵌入页面在受限环境中运行。遵循安全指南就没问题。

"MCP Apps 不是会替代这个吗？"

MCP Apps 需要平台集成——你的应用只能在支持 MCP 的平台上运行。ERI 只是一个 URL，在所有平台上都能用。作为第三方提供者，ERI 让你以最小代价获得最广覆盖。

"如果我们的平台不支持 iframe 怎么办？"

ERI 会降级为纯文本输出——Agent 仍然通过文字提供价值。大多数主流平台（ChatGPT、Claude、Gemini）今天都支持渲染 iframe，所以这很少成为问题。

内部推介模板

向团队或领导层介绍 ERI 时：

我们可以在不到一天内让现有的 Web 应用出现在 AI Agent 对话中。无需新协议、无需 SDK、无需平台改动。只需要一个 markdown 文件（skill.md），告诉 Agent 如何调用我们的 API 和构造嵌入 URL。

作为第三方服务，这意味着我们的应用能在任何 Agent 平台上使用——ChatGPT、Claude、Gemini——不需要为每个平台单独做集成。我们控制体验。一个嵌入页面，一个 skill 文件，到处运行。
