采用 ERI — 团队指南

在组织内评估、规划并上线交互式 Agent 输出。

ERI 适合你吗？

适合：你有 Web 应用，想让它在任何 Agent 对话中被嵌入——ChatGPT、Claude、Gemini——无需平台 SDK。不适合：自建渲染器（用 A2UI）、全面投入 MCP（用 MCP Apps）、或需要实时同步。

快速体验 — 5 分钟

在做任何承诺之前，先看看 ERI 的效果：

  1. 打开在线演示——看一个 Agent 嵌入的可交互计算器
  2. 编辑计算器中的数字——结果即时更新，无需等待
  3. 给你的团队看："这就是我们的应用在 ChatGPT 里能呈现的样子"

如果这引起了兴趣，继续往下看采用清单。

采用清单

第一阶段：试点（共 1 天：skill.md 约 10 分钟，其余是嵌入页面）

  • 选择一个现有 Web 应用进行嵌入
  • 创建一个精简的 /embed 路由（约 40 行代码）
    • 从 URL hash 或 query 参数读取初始状态
    • 自包含——不依赖宿主页面
    • 使用 HTTPS
    • 校验和清理所有来自 URL 的输入（绝不要对用户数据使用 eval()）
  • 按照规范写一个 skill.md
  • 在你的 Agent 平台上测试——确认 iframe 能正确渲染

第二阶段：集成（1 周）

  • 确认 iframe 渲染时添加了 sandbox="allow-scripts allow-same-origin"
  • 测试不同嵌入宽度下的响应式表现
  • 确认嵌入页面没有使用 document.cookie、window.top 或 window.opener
  • 处理边界情况：无效 URL 参数、慢网络、空状态

第三阶段：打磨（可选）

  • 通过 URL 参数或 prefers-color-scheme 添加主题适配（亮/暗）
  • 实现 postMessage 以支持 Level 2 双向通信
  • 监控嵌入页面的性能和加载时间

常见疑问

"iframe 不是过时了吗？"

iframe 是所有主要平台（YouTube、Stripe、Google Maps）嵌入第三方内容的方式。ChatGPT、Claude、Gemini 都在 Agent 输出中渲染 iframe。Web 并没有淘汰 iframe——而是通过 sandbox 属性将其标准化和安全化。

"安全怎么办？"

平台对 iframe 加沙箱（sandbox="allow-scripts allow-same-origin"）——无法访问父页面 cookie、token 或 DOM。遵循标准 XSS 防护即可。详见规范安全章节。

"MCP Apps 不是会替代这个吗？"

MCP Apps 只在 MCP 平台上运行。ERI 只是一个 URL——所有平台通用。最广覆盖，最小代价。

"我们的 API 需要认证——Agent 怎么传凭证？"

Agent 从服务端调用你的 API，不是从用户浏览器。提供一个专门的公开 API 端点供 Agent 访问——限流、限定为只读或安全操作。对于敏感操作，让用户在嵌入页面内自行认证（OAuth 弹窗等）。嵌入页面（iframe）只负责渲染结果——不需要直接调用你的 API。

"如果我们的平台不支持 iframe 怎么办？"

ERI 会降级为纯文本输出——Agent 仍然通过文字提供价值。大多数主流平台（ChatGPT、Claude、Gemini）今天都支持渲染 iframe，所以这很少成为问题。

内部推介模板

我们可以在一天内让 Web 应用出现在 AI Agent 对话中。无需协议、无需 SDK——只需一个 skill.md，告诉 Agent 如何调用我们的 API 并嵌入 UI。

一个嵌入页面，所有 Agent 平台通用——ChatGPT、Claude、Gemini——无需逐平台集成。我们控制体验。
