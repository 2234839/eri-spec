超越文字：为什么 AI Agent 需要交互式 UI

发布日期：2026-05-15

文字陷阱

今天的 AI Agent 都有同样的问题。你让它算个东西，它回复：

99.5 × 3 = 298.5

对的。但你想看 4 件是多少。或者 5 件。或者加 8% 的税。每次变化都意味着又一轮对话——描述想改什么，等回复，再描述下一个。

问题不是准确性。问题是媒介。

不只是计算。Agent 生成图表时，你想调坐标轴。创建表单时，你想改字段。选颜色时，你想拖滑块。每次 Agent 都把你逼回文字——而你需要的明明是一个 UI。

Agent 生态解决了输入——自然语言、工具调用、多模态。没解决输出。结果都回到文字。

引入 ERI

ERI（Embedded Result Interface）是一种让 Agent 输出可交互的约定。Agent 调用第三方 API，构造嵌入 URL，输出 iframe 或截图。用户直接交互——Agent 不在循环中。

不需要新协议。不需要 SDK。只需要一个 skill.md。

---
name: notecalc
description: 数学计算器，支持变量和单位转换。
---

## 工作流
1. 将用户请求转化为表达式
2. 调用 POST /api/calculate 传入表达式
3. 以 iframe 嵌入结果: https://app.com/embed#encoded_expr

10 分钟写完。半天做好嵌入页面。零平台改动。Level 1（截图）现在就能用——不需要平台支持。上线，准备好时升级到 Level 2（iframe）。不会破坏任何东西。

三条路径到交互式 Agent 输出

业界从三个方向收敛到同一个问题：

MCP Apps（Anthropic & OpenAI, 2025）在 MCP 生态中标准化交互式 UI——沙箱 iframe 表现为小应用。适合 MCP 优先的平台。

A2UI（Google, 2025）走声明式、跨平台路线——Agent 发送 JSON 组件描述，客户端库（Flutter、Web Components）原生渲染。适合构建自己渲染管线的平台。

ERI 走最简单的路——嵌入已有的东西。一个已有 Web UI 的应用，半天就能出现在 Agent 对话中。没有 SDK、没有 Schema、没有渲染器、不需要 MCP 集成。一个 URL。今天就能用，以后再采用 MCP Apps 或 A2UI。三条路收敛到同一个终点。
