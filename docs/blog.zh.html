超越文字：为什么 AI Agent 需要交互式 UI

发布日期：2026-05-15

文字陷阱

今天的 AI Agent 都有同样的问题。你让它算个东西，它回复：

99.5 × 3 = 298.5

对的。但你想看 4 件是多少。或者 5 件。或者加 8% 的税。每次变化都意味着又一轮对话——描述想改什么，等回复，再描述下一个。

问题不是准确性。问题是媒介。不只是计算——图表需要可调的坐标轴，表单需要可编辑的字段，配色需要可拖动的滑块。每次 Agent 都把你逼回文字。

生态解决了输入，没解决输出。

引入 ERI

ERI（Embedded Result Interface）让你的 Web 应用以实时可编辑的 UI 出现在任何 Agent 对话中——ChatGPT、Claude、Gemini。你控制体验。用户直接交互——无需等待 Agent 来回。

不需要新协议。不需要 SDK。不需要平台审批。只需一个 skill.md，告诉 Agent 如何调用你的 API、嵌入哪个 URL。见规范中的最小示例——只需 4 行指令。

10 分钟写完。半天做好嵌入页面。零平台改动。今天就能上线。现在试试。

为什么先选 ERI

MCP Apps 和 A2UI 提供更丰富的能力——但只限于支持它们的平台。ERI 提供所有平台即日可用，因为只是一个 URL 在 iframe 里。无需运行时、无需渲染器、无需平台配合。

你为 ERI 构建的嵌入页面，就是日后打包给 MCP Apps 用的同一个页面。ERI 是入口：零成本上线，等目标平台支持更丰富的协议时再迁移。

ERI 有真实的权衡（快照式、无原生 API）。完整列表见规范中的局限性章节。
