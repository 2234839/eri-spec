Adopting ERI — Team Guide

Evaluate, plan, and ship interactive Agent output in your organization.

Is ERI Right for You?

Fits: you have a web app and want it in any Agent conversation — ChatGPT, Claude, Gemini — without platform SDKs.

Doesn't fit: building your own renderer (use A2UI), all-in on MCP (use MCP Apps), or need real-time sync.

Quick Experience — 5 Minutes

See ERI in action before committing to anything:

  1. Open the live demo — see an interactive calculator embedded by an Agent
  2. Edit the numbers in the calculator — results update instantly, no round trip
  3. Show your team: "This is what our app could look like inside ChatGPT"

If that sparks interest, proceed to the checklist below.

Adoption Checklist

Phase 1: Pilot (1 day total: ~10 min for skill.md, the rest is the embed page)

  • Pick one existing web app to embed
  • Create a stripped-down /embed route (see minimal example)
    • Reads initial state from URL hash or query params
    • Self-contained — no dependency on host page
    • Served over HTTPS
    • Validate and sanitize all URL-sourced inputs (never eval() user data)
  • Write a skill.md — start from the copy-paste template
    • Placement varies by platform: Custom Instructions (ChatGPT), CLAUDE.md or skill files (Claude), system instructions (Gemini), or any Agent behavior definition mechanism
  • Test with your Agent platform — confirm iframes render with sandbox="allow-scripts"

Phase 2: Integration (1 week)

  • Test responsive behavior at different embed widths
  • Verify no document.cookie, window.top, or window.opener usage in embed page
  • Handle edge cases: invalid URL params, slow networks, empty state

Phase 3: Polish (optional)

  • Add theme adaptation (light/dark) via URL param or prefers-color-scheme
  • Implement postMessage for Level 2 bidirectional communication
  • Monitor embed page performance and load time

Common Objections

"Isn't iframe outdated?"

Iframe is how every major platform (YouTube, Stripe, Google Maps) embeds third-party content. ChatGPT, Claude, and Gemini all render iframes in Agent output today. The web hasn't replaced iframes — it standardized them with sandbox attributes for security.

"What about security?"

Platforms sandbox iframes (sandbox="allow-scripts") — no access to parent cookies, tokens, or DOM. Follow standard XSS prevention. See spec security section.

"MCP Apps will replace this, right?"

MCP Apps only work on MCP-enabled platforms. ERI is a URL — works everywhere. And the embed page you build for ERI is the same page you'd package for MCP Apps later. ERI is the on-ramp, not a dead end.

"Our API requires authentication — how does the Agent pass credentials?"

The Agent calls your API from its server, not from the user's browser. Provide a dedicated public API endpoint for Agent access — rate-limited, scoped to safe operations. For sensitive operations, let users authenticate within the embed page itself (OAuth popup, etc.). The iframe only renders results — it doesn't call your API.

"What about PII and compliance?"

Never place PII in URL hash or query params — URLs are logged in browser history, proxy logs, and referrer headers. For data that involves PII, pass a short-lived token in the URL and fetch actual data via an API call inside the embed page. The embed page runs under the platform's iframe sandbox — no access to parent cookies or tokens.

"What if our platform doesn't support iframes?"

ERI falls back to plain text — the Agent still provides value. Most major platforms (ChatGPT, Claude, Gemini) render iframes today, so this is rarely an issue.

Internal Pitch Template

We can embed our web app's UI directly inside AI Agent conversations — the user sees our product, interacts with it, and never leaves the chat. It takes one embed page and a skill.md that tells the Agent how to call our API.
