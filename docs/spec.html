ERI Specification — Embedded Result Interface

Version: 1.0  |  Status: Stable  |  License: MIT

1. Definition

ERI (Embedded Result Interface) is a Skill authoring pattern. After an Agent processes a user request, it outputs an interactive embedded UI (iframe) instead of (or in addition to) plain text. The user can directly interact with this UI.

Who does what in ERI:

  • Agent Understands intent, calls API, constructs embed URL, outputs UI — this is what any AI Agent already does (read a skill, call APIs, output text). No platform change needed.
  • Provider Writes skill.md and provides an HTTPS embed page — this is the only thing a third-party app needs to do. ~40 lines of code.
  • Platform Required for iframe rendering — most platforms already render iframes. No platform support needed for plain text fallback.

Core constraints:

  • No new protocol, no new fields — implemented through conventions in skill.md
  • Agent does not actively monitor the output UI — each new instruction generates a fresh UI
  • Third-party app runs independently — only needs to provide an HTTPS page

2.1 Understand Intent

Agent Agent's natural capability — reading a skill and extracting parameters from user input.

The Agent extracts structured parameters from user input. For example:

  • "Calculate 3 items at $99.5 each" → expression 99.5 * 3
  • "Convert 5 kg to grams" → unit conversion 5 kg to g

2.2 Call API

Agent Standard tool calling — the Agent already knows how to call HTTP APIs.

The Agent calls the third-party app's API to compute results. The API returns structured JSON.

POST /api/calculate
Body: {"content": "99.5 * 3"}
Response: {"result": 298.5}

2.3 Construct Embed URL

Agent String construction — the Agent follows the skill.md template to build a URL.

Encode the initial data into the URL (hash params, query params, or backend session).

https://app.example.com/embed#99.5 * 3

2.4 Output UI

Agent outputs markup. Platform renders it.

<iframe src="https://app.example.com/embed#encoded_data" width="100%" height="400"></iframe>

Security attributes (sandbox, etc.) are added automatically by the Agent platform. If the platform cannot render iframes, it falls back to plain text output.

3. Conversation Flow

User modifications in the embedded UI do not automatically notify the Agent. When the user starts a new turn:

  1. The Agent reads previous results from conversation context
  2. Combines the new input with previous context, calls the API again
  3. Outputs a brand new embedded UI (does not update the old one)
User: "Calculate 3 items at $99.5 each"
Agent: [outputs iframe: 99.5 * 3 = 298.5]

(user modifies values in the iframe — Agent is unaware)

User: "Add 8% tax"
Agent: Reads context last_result=298.5, computes 298.5 * 1.08
       [outputs new iframe: 298.5 * 1.08 = 322.38]

4. Skill Authoring Provider

A minimal ERI Skill in skill.md:

---
name: tool-name
description: What this Skill does
---
## Workflow
1. Extract parameters from user input
2. Call API: POST https://api.example.com/calculate
   Body: {"expr": "expression"}
3. Construct embed URL: https://app.example.com/embed#URLEncoded(expr)
4. Output UI (priority: iframe > plain text)

The Agent reads this workflow, executes each step, and outputs an iframe.

Minimal Embed Page Example

<!DOCTYPE html>
<html>
<body>
<input id="expr" style="width:100%;font-size:18px">
<div id="result" style="font-size:24px;margin-top:8px"></div>
<script>
  const expr = decodeURIComponent(location.hash.slice(1));
  document.getElementById('expr').value = expr;
  function update() {
    const v = document.getElementById('expr').value;
    try { document.getElementById('result').textContent = eval(v); }
    catch(e) { document.getElementById('result').textContent = ''; }
  }
  document.getElementById('expr').oninput = update;
  update();
</script>
</body>
</html>

20 lines. Reads from URL hash, self-contained, instant interaction. Deploy this to any HTTPS host and you have a working ERI embed page.

6. Security

Agent platform side Platform

  • iframes must include sandbox attribute to restrict permissions
  • Recommended: sandbox="allow-scripts allow-same-origin"
  • User credentials must not be passed to third-party iframes

Third-party app side Provider

  • Don't rely on document.cookie (may be unavailable in sandbox)
  • Don't use window.opener or window.top
  • Sanitize all inputs against XSS

  data: { ... }

8. Use Cases

Fits: Calculators, forms/surveys, data visualization, document editing, design tools, code editors — any scenario where the user wants to tweak the Agent's output.

Does not fit: Pure information queries (no interaction needed), long-form text generation, real-time sync (ERI is snapshot-based).

10. Industry Landscape

Three approaches exist for interactive Agent output:

  • ERI — embed any web app via URL. Works on all platforms. You control the UI.
  • MCP Apps (Anthropic & OpenAI) — sandboxed mini-apps in the MCP ecosystem. Works only on MCP-enabled platforms.
  • A2UI (Google) — Agent declares UI as JSON, client renders natively. Works only on A2UI-enabled platforms.

ERI is not opposed to MCP Apps or A2UI — it's the on-ramp. As a third-party provider, ERI gives you the broadest reach with the least effort. Embed today, adopt richer protocols when your platforms support them.
