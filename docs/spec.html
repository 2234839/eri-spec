ERI Specification — Embedded Result Interface

Version: 1.0  |  Status: Stable  |  License: MIT

1. Definition

ERI (Embedded Result Interface) is a convention for making Agent output interactive. After processing a user request, the Agent outputs an embedded UI (iframe) instead of plain text — using only a skill.md and a URL. No new protocols, no SDKs.

Who does what in ERI:

  • Agent Understands intent, calls API, constructs embed URL, outputs UI
  • Provider Writes skill.md and provides an HTTPS embed page (~40 lines)
  • Platform Renders iframes (most already do)

Core constraints:

  • Snapshot-based — the Agent does not monitor the output UI. Each new instruction generates a fresh UI (see Section 3)
  • Third-party app runs independently — only needs to provide an HTTPS page

2. Workflow

1. UnderstandExtract intent
→
2. Call APIGet structured data
→
3. Construct URLEncode params
→
4. Output UIiframe / plain text

Steps 1 and 3 are the Agent's natural capabilities. The two steps involving external systems:

2.1 Call API Agent

The Agent calls the third-party app's API from the server side (not from the user's browser). Standard HTTP, structured JSON. No CORS configuration needed.

POST /api/calculate
Body: {"content": "99.5 * 3"}
Response: {"result": 298.5}

2.2 Output UI Agent Platform

<iframe src="https://app.example.com/embed#encoded_data" width="100%" height="400"></iframe>

Platforms add sandbox automatically. No iframe support? Falls back to plain text.

3. Conversation Flow

Iframe edits don't notify the Agent. On each new turn:

  1. Agent reads previous results from context
  2. Combines new input with context, calls API again
  3. Outputs a fresh embed (old one is not updated)
User: "Calculate 3 items at $99.5 each"
Agent: [outputs iframe: 99.5 * 3 = 298.5]

(user modifies values in the iframe — Agent is unaware)

User: "Add 8% tax"
Agent: Reads context last_result=298.5, computes 298.5 * 1.08
       [outputs new iframe: 298.5 * 1.08 = 322.38]

4. Skill Authoring Provider

A skill.md file is placed where the Agent can discover it — as a custom instruction, a GPT action, a Claude skill file, or any mechanism the platform provides for defining Agent behavior. The format is the same across all platforms.

A minimal ERI Skill:

---
name: tool-name
description: What this Skill does
---
## Workflow
1. Extract parameters from user input
2. Call API: POST https://api.example.com/calculate
   Body: {"expr": "expression"}
3. Construct embed URL: https://app.example.com/embed#URLEncoded(expr)
4. Output as iframe (fallback to plain text if platform cannot render)

The Agent reads this workflow, executes each step, and outputs an iframe.

The frontmatter (name, description) follows standard YAML convention. The ## Workflow section is freeform — write it in whatever natural language the Agent understands. No special syntax needed.

5. Embed Page Requirements Provider

RequirementDescription
HTTPSMust serve over HTTPS
URL param readingRead initial state from URL hash / query
Self-containedHandle all interactions internally. No host JS/CSS dependencies. Responsive layout.
postMessage (optional)Notify host of changes inside the iframe
Theme adaptation (optional)Read URL params or host colors to match light/dark theme

Minimal Embed Page Example

<!DOCTYPE html>
<html>
<body>
<input id="expr" style="width:100%;font-size:18px">
<div id="result" style="font-size:24px;margin-top:8px"></div>
<script>
  const expr = decodeURIComponent(location.hash.slice(1));
  document.getElementById('expr').value = expr;
  function safeEval(s) {
    return /^[0-9+\-*/().%\s]+$/.test(s)
      ? Function('"use strict"; return (' + s + ')')()
      : NaN;
  }
  function update() {
    const v = document.getElementById('expr').value;
    const r = safeEval(v);
    document.getElementById('result').textContent =
      isNaN(r) ? '' : r;
  }
  document.getElementById('expr').oninput = update;
  update();
</script>
</body>
</html>

24 lines. Deploy to any HTTPS host.

6. Security

Agent platform side Platform

  • Add sandbox="allow-scripts allow-same-origin" to iframes
  • Never pass user credentials to third-party iframes

Third-party app side Provider

  • Don't rely on document.cookie (may be unavailable in sandbox)
  • Don't use window.opener or window.top
  • Sanitize all inputs against XSS

7. Progressive Levels

LevelCapabilityWho needs to act
0Plain text outputAgent only — nothing else needed
1iframe embeddingProvider embed page + Platform iframe support (most already have this)
2Bidirectional communicationLevel 1 + Provider Platform both implement postMessage

Level 2 postMessage protocol (use specific origin, not "*"):

// iframe → Agent platform
window.parent.postMessage({
  type: "eri:valueChanged",
  path: "field.path",
  value: newValue
}, "https://agent-platform.example.com");

// Agent platform → iframe (optional, Level 2)
iframe.contentWindow.postMessage({
  type: "eri:update",
  data: { ... }
}, "https://your-app.example.com");

8. Use Cases

Fits: Calculators, forms/surveys, data visualization, document editing, design tools, code editors — any scenario where the user wants to tweak the Agent's output.

Does not fit: Pure information queries (no interaction needed), long-form text generation, real-time sync (ERI is snapshot-based).

9. Limitations

  • Snapshot-based — Agent cannot see iframe edits in real time. Use Level 2 postMessage for bidirectional sync.
  • No native device access — iframes cannot use GPS, camera, or other device-native APIs.
  • No SEO indexing — iframe content is invisible to search engines (irrelevant for Agent output).

10. Industry Landscape

Three approaches exist for interactive Agent output:

  • ERI — embed any web app via URL. Works on all platforms.
  • MCP Apps (Anthropic & OpenAI) — sandboxed mini-apps in the MCP ecosystem. MCP-enabled platforms only.
  • A2UI (Google) — Agent declares UI as JSON, client renders natively. A2UI-enabled platforms only.

ERI is the on-ramp: broadest reach, least effort. Embed today, adopt richer protocols when your platforms support them. See blog post for detailed comparison.
